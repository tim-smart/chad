## Question

Do the credential tools hold when they are run: a value reaching a child process by name, masking at chad's outputs, the Enter button and modal, and a real sign-in through a browser?

"Credential tools: stored logins and one-off codes for tools that sign in" (TIM-546) was agreed from reading, with Architect standing in for Tim. Nothing in v1 uses these tools end to end, so this ticket is the only run they get before the build. Its resolution comment holds the twenty-one decided points.

Claims to run, on real clanka 0.27.0 with a scripted model:

- `chad secret run --env VAR=NAME -- <command>` through the spawner chad wraps. The `Calling "bash"` line in the script's output shows names only, and the child sees the value. `--stdin NAME` writes the value with no trailing newline and closes stdin. A missing name exits 125, and the child's own exit code passes through.
- `chad secret code NAME` against the RFC 6238 vectors, the wait when under 5 seconds are left in a window, and the refusal for a secret that is not TOTP.
- The masking floor. A stored value of 8 characters or more does not appear in the history rows chad writes, the status message, the log, the `turns` table, anything chad posts to chat, or the messages an `afterTurn` hook receives. After the run, grep the log, the database, `home/`, the posted answer and what the hooks received for the value.
- The better version of masking: wrapping clanka's `AgentExecutor` so the value is also kept out of the model's context for the rest of the turn. clanka has no redaction hook, and this seam was read and never tried (`src/AgentExecutor.ts:70-74`, `src/Agent.ts:1055-1085` at `88a1e05`).
- The Enter button and the modal on `ChatTest`: the modal's reply inside Discord's 3 seconds, a click from someone who is not an owner ignored, the submit stored through the same path as `chad secret set`, and the message edited to "Saved NAME".
- `chad secret request` waiting 5 minutes inside clanka's `bash` with `timeoutMs: 330000`, and whether clanka puts any limit on the `execute` script that wraps that call. `run` moves a command to the background after 120 seconds, so the skill forbids it here.
- An owner message in the thread ends a pending request with exit 1, and the message steers the turn as usual. `/stop` during a request kills the child, and the daemon edits a `--code` message to "Cancelled".
- `chad secret request --code` returns the typed code on stdout and stores nothing.
- A repeat request for the same name in the same thread posts no second button. Saving the name by any path edits every remembered button for it to "Saved NAME".
- agent-browser installed on the volume, driving a Chromium sidecar over CDP, signing in to a small local test form with a password and a TOTP: `chad secret run --stdin NAME -- agent-browser auth save ... --password-stdin`, then `auth login`, then the code from `chad secret code`.
- The Playwright MCP recipe. `--secrets` takes a dotenv file, so the recipe has to turn `${NAME}` from `mcp.json` into that file without leaving a plaintext copy on the volume, through process substitution or a file under `/dev/shm`. Nobody has looked at this step. Also run a secret change that restarts the server while a login is in progress.

Decide:

- Whatever the run contradicts. Each contradiction goes back to Tim as a question, with the closed ticket named.
- Whether the `AgentExecutor` wrap ships, or v1 has the floor alone.
- The Playwright MCP recipe the `credentials` skill carries, or that the skill carries none.

Not in this ticket: a real Discord modal, which needs a real bot token like the rest of the Discord gateway.

Prototype: extend the hosts from "The Session entity run on SingleRunner and SQLite" (TIM-543) and "The chad CLI's socket, lock and session marker run for real" (TIM-550), and keep the log of each run.
